==================================================
1. PROJECT SUMMARY
==================================================

This repository is a static multi-language random-pick web product.
The product is built as mostly self-contained HTML pages with large inline
CSS/JS blocks plus a small shared asset layer in assets/js and a script layer
in scripts/.

Primary product families:

1. Wheel / roulette spinner
2. Lucky Draw / random number generator
3. Ladder Draw
4. Team Generator / Team Split
5. Coin Flip
6. Dice Roll

The Korean root path is the default root publishing structure. English and
other languages are published as path-based localized versions.

Current major goals reflected in the codebase:

- Strong English SEO acquisition
- Full localized tool coverage across major languages
- Static deploy safety through predeploy validation
- Consistent shared header/navigation across all game/tool pages
- Stable 3D dice/coin rendering using pinned model-viewer

4. ARCHITECTURE STYLE
==================================================

The product is not a React/Vue/Next application.
It is a static HTML site with:

- large single-file tool pages

- inline tool runtime logic

What each does at a high level:

assets/js/utils.js
- Shared utility layer used by multiple tools.
- Includes download helpers and common formatting helpers used by team
  generator and other pages.

assets/js/random.js
- Shared randomness helper layer exposed as window.RLTRandom.
- Used by team-generator and potentially other pages for shuffling.

assets/js/i18n.js
- Shared locale helpers for parts of the product.
- Not all pages rely on it equally; many core pages still embed their own
  locale maps inline.

assets/js/lotto.js
- Runtime for lucky draw / number draw behavior.

assets/js/ladder.js
- Runtime for ladder draw behavior.

assets/js/team-generator-i18n.js
- Centralized team-generator locale data map.
- Holds SEO strings, nav strings, hero text, labels, FAQ, examples,
  messages, and language metadata for all 18 team-generator locales.
- The team-generator locale rollout now depends on this file as the single
  source of truth.

assets/js/team-generator.js
- Team-generator runtime.
- Parses pasted roster data.
- Detects header rows automatically.
- Supports name-only mode and name+score mode.
- Supports tab-separated Excel paste, slash, comma, pipe, and whitespace forms.
- Uses balanced mode heuristics that try multiple random candidates and keep
  a more stable assignment while respecting team-size limits.
- Supports copy/export/fullscreen/state persistence.

assets/js/third-party-loader.js
- Shared loader for third-party integrations such as Userback.
- Footer contact links were updated so they open Userback first on plain click.

9. CURRENT I18N MODEL
==================================================

The localization model is mixed:

1. Main tool pages (home, dice, coinflip, etc.)
   - Large HTML files contain inline locale maps and inline runtime.
   - The English page is not the only source of truth; many locale pages embed
     English locale blocks inside their own HTML.
   - This is why some English copy changes had to be propagated across many
     localized pages, not just /en/ pages.

2. Team generator
   - More centralized than the rest.
   - assets/js/team-generator-i18n.js is the main locale data source.
   - scripts/sync-team-generator-locales.js can regenerate/sync static locale
     HTML from that data.

3. Legal pages
   - Localized only for a limited language subset:
     en, ja, zh-cn, zh-tw

11. DICE / COIN 3D RUNTIME
==================================================

This area had a major regression and root-cause investigation.

Important files:

- dice/index.html
- en/dice/index.html
- ... all localized dice pages
- coinflip/index.html
- en/coinflip/index.html
- ... all localized coinflip pages

Critical static assets:

- /dice.glb
- /stylized_pirate_coin.glb

Current correct runtime rule:

- All dice and coin pages must load:
  https://unpkg.com/@google/model-viewer@3.5.0/dist/model-viewer.min.js

They must not load:

- https://unpkg.com/@google/model-viewer/dist/model-viewer.min.js

Why:

- The older unversioned model-viewer URL caused runtime behavior drift with no
  repo diff.
- The product relied on model-viewer orientation updates for visible 3D motion.
- When the floating runtime changed, sound/results still worked but visible 3D
  motion stopped rendering reliably.

Important rule:

- Do not reintroduce wrapper transform fake rotation.
- That workaround made the uploaded 3D assets look flat / 2D.

Current validator guards:

- pinned model-viewer URL must exist
- floating model-viewer URL must not exist
- /dice.glb reference must exist on dice pages
- /stylized_pirate_coin.glb reference must exist on coin pages

Important doc:

- DICE_COIN_MOTION_ROOT_CAUSE_2026-03-15.md

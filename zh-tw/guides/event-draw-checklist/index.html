活動抽籤檢查清單

公開抽獎或直播前，先檢查參與名單、規則顯示、畫面配置、紀錄方式與一次試跑，可以大幅降低臨場失誤。

檢查重點

  • 先檢查重複報名與最後一刻的名單變動。
  • 開始前把規則明確展示給參與者看。
  • 正式上線前先測試全螢幕、聲音與結果保存。

在 Randomly Pick 中怎麼用

在準備梯子抽籤、贈品抽獎、課堂點名或直播活動時，把這份清單放在旁邊逐項確認。

Event Draw Checklist

Even when the tool is ready, draw operators often miss the same steps right before launch: incomplete participant lists, duplicate entries, unclear rules, and missing result records. This checklist covers the minimum checks worth making before you press the button.

1. Participant list review

  • Are all intended participants included?
  • Do names or numbers match the latest source list?
  • Are duplicate entries removed?
  • Is the draw based on individuals, teams, or ticket numbers?

List review should finish first. If list problems appear after the draw, people remember the operational mistake more than the random result.

2. Rule announcement

  • Will winners be excluded from later rounds?
  • Can the same person win again?
  • Under what conditions is a redraw allowed?
  • Are you drawing one result at a time or multiple results in sequence?

The operator knowing the rules is not enough. Participants should know them too. Read the rules briefly before the draw and keep them visible on screen if possible.

3. Screen readiness

On mobile screens and live broadcasts, parts of the UI are easy to hide accidentally. Before you start, confirm that the participant list, settings, main action button, and result area are all visible. If you plan to use fullscreen mode, test it once before the event begins.

4. Result recording plan

When the event gets busy, it is easy to forget the record after the draw ends. Decide in advance whether you will save a CSV, take a capture, or maintain a separate event log. Having that plan makes follow-up questions much easier to answer later.

5. Run one dry test

A single dry run before the real event is one of the cheapest ways to prevent public mistakes. Check that sound levels are reasonable, the participant list is applied correctly, exclusion rules behave as expected, and the result log is working.
